# 宝宝成长时间轴 App 设计规格

## 1. 产品目标

为单个家庭提供一个运行在 iPhone 和 Android 上的单机 App，用统一时间轴记录并回顾宝宝的成长。第一版优先保证记录简单、回顾直观和本地数据可靠，不提供账号或联网能力。

成功标准：用户能在几秒内添加一条记录，并能从按日期组织的时间轴中可靠地回看照片、成长数据、日常活动和成长里程碑；卸载 App 前可主动导出完整备份。

## 2. 第一版范围

### 包含

- 一个宝宝的本地资料：头像、姓名、生日和可选性别
- 统一成长时间轴
- 四类记录：珍贵时刻、成长数据、日常活动、里程碑
- 记录的新增、查看、编辑和删除
- 按日期浏览及按记录类型筛选
- 本地完整备份、校验和恢复
- iPhone 与 Android 支持

### 不包含

- 登录和账号体系
- 服务端、云数据库或云同步
- 家庭多人实时协作
- 医生或育儿顾问的远程访问权限
- 智能提醒、异常判断和复杂统计
- 多宝宝管理

医生或家庭成员需要查看内容时，第一版仅能由用户在设备上展示，或在后续迭代中增加分享能力。实时协作和权限控制必须等云端版本实现。

## 3. 信息架构

底部导航包含三个入口：

1. **时间轴**：默认首页，按发生时间倒序展示全部记录。
2. **添加**：中央主操作，用于快速创建四类记录。
3. **宝宝**：编辑宝宝资料、导出备份、恢复备份和清空数据。

所有内容最终表现为统一的时间轴记录。首页按“今天”“昨天”或具体日期分组，并允许按记录类型筛选。

## 4. 核心界面与交互

### 时间轴首页

- 顶部展示宝宝头像、姓名和由生日计算出的当前月龄。
- 照片记录使用大图卡片；数据和日常活动使用紧凑卡片。
- 卡片展示发生时间、类型图标和摘要。
- 点击进入详情；详情页提供编辑与删除。
- 删除前必须二次确认。

### 添加记录

- **珍贵时刻**：照片或视频、文字、发生时间；文字或媒体至少填写一项。
- **成长数据**：身高、体重、头围、测量时间；三个测量值至少填写一项。
- **日常活动**：喂奶、睡眠或换尿布，可填写数量、时长和备注；活动类型必填。
- **里程碑**：预设标签或自定义标题，可附文字和照片；标题必填。
- 发生时间默认为当前时间，但允许修改。

### 宝宝页面

- 姓名和生日必填；头像和性别可选。
- 支持导出包含数据库与媒体文件的完整备份。
- 恢复前检查备份完整性；只有校验通过后才替换当前数据。
- 清空数据需二次确认，并明确说明操作不可撤销。

## 5. 视觉方向

整体采用“温暖手账 + 极简相册”的混合风格：奶油白背景、柔和暖色点缀、圆角卡片和充足留白。照片是主要视觉内容，不使用大量幼稚插画或高饱和装饰，以保证长期使用仍然耐看。

## 6. 技术架构

第一版完全单机，无服务端，也不存在服务端语言。

- **客户端**：React Native + Expo + TypeScript，一套代码支持 iOS 和 Android。
- **结构化数据**：设备内嵌 SQLite，保存宝宝资料、记录、附件索引和元数据。
- **媒体文件**：复制到 App 私有文件目录，并为列表生成缩略图。
- **备份模块**：将数据库、媒体文件和带版本号的清单打包导出；恢复时校验清单及文件完整性。

代码按职责拆分：

- 时间轴模块：查询、分组、筛选和渲染统一记录。
- 记录编辑模块：四类表单、输入校验和记录写入。
- 宝宝资料模块：资料编辑与月龄计算。
- 媒体模块：导入、复制、缩略图和孤立文件清理。
- 备份模块：导出、校验、恢复和版本兼容检查。
- 数据访问层：封装 SQLite 读写和事务，不让界面直接执行 SQL。

## 7. 数据模型

所有时间轴内容使用统一的 `records` 主记录，并由类型详情表保存专属字段。

- `baby`：`id`、`name`、`birth_date`、`sex`、`avatar_path`、创建及更新时间。
- `records`：`id`、`type`、`occurred_at`、`note`、创建及更新时间。
- `growth_details`：`record_id`、`height_cm`、`weight_kg`、`head_cm`。
- `activity_details`：`record_id`、`activity_type`、`amount`、`duration_minutes`。
- `milestone_details`：`record_id`、`title`、`preset_key`。
- `attachments`：`id`、`record_id`、`media_type`、`file_path`、`thumbnail_path`、`created_at`。

SQLite 外键与唯一约束用于防止孤立详情；删除主记录时在同一事务中删除详情和附件索引。实际媒体文件在数据库事务成功后清理，失败的文件清理任务可在下次启动时重试。

## 8. 数据流与错误处理

保存记录的流程：选择类型 → 填写内容 → 校验 → 将媒体复制到临时位置 → 开启 SQLite 事务并写入记录与附件索引 → 将媒体移入正式文件位置 → 提交事务 → 刷新时间轴。

如果媒体复制或正式落盘失败，SQLite 事务回滚；如果数据库提交失败，已经移入正式位置的本次媒体会被清理。失败操作不会留下可见的半条记录。临时文件和未被数据库引用的媒体会在失败后立即清理，并在下次启动时再次扫描兜底。

其他规则：

- 无效数值、未来生日、无法识别的媒体格式均在提交前提示。
- 存储空间不足时停止保存并保留已有数据。
- 时间轴发现媒体文件缺失时显示占位提示，不能因此导致页面崩溃。
- 备份恢复采用“校验 → 解包到临时目录 → 打开数据库并检查版本 → 原子替换”的流程；任何步骤失败都保留当前数据。
- App 不提供医疗诊断或成长异常判断。

## 9. 测试与验收

- 四类记录均能新增、查看、编辑和删除。
- 时间轴按发生时间倒序排列，跨天与跨时区分组正确。
- 类型筛选结果正确，清除筛选后恢复完整时间轴。
- App 重启后记录及媒体仍可访问。
- 身高、体重、头围等输入拒绝非数字、负数和明显超出预设输入范围的值；输入范围仅用于防止误输，不构成医学判断。
- 修改生日后月龄正确更新。
- 数据库或媒体写入失败不会产生半条记录。
- 导出的备份可在清空测试数据后完整恢复。
- 损坏、缺文件或版本不受支持的备份不会覆盖当前数据。
- 在至少一台 iPhone 和一台 Android 真机上验证“创建资料 → 添加四类记录 → 浏览与编辑 → 导出 → 恢复”的核心流程。

## 10. 后续演进

若未来增加账号、家庭协作和医生查看，再引入服务端。优先考虑 TypeScript + Node.js（例如 NestJS），以复用客户端的数据类型和校验规则。云端版本需要重新设计身份认证、细粒度授权、加密、隐私合规、媒体存储和同步冲突处理；这些均不属于第一版。
